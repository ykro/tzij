## Method

- chrF++ = sacrebleu CHRF with word_order=2, corpus level, on text normalized by `data/normalize.py` (hypotheses and references alike).
- Same instructions for every model (`duel/tzij_duel/prompts.py`, version `tzij-translate-v1`); `+rag` variants also get the top 6 examples and glossary entries from the retrieval index (train split only).
- Latency: wall clock per translation, retrieval included; local models one request at a time.
- Cost: Gemini tokens × list price (input $0.75/M, output $3.75/M, thinking billed as output). Local inference counted as $0.
- Fine-tuned variants appear here automatically when `FINETUNED_MODEL_TAGS` lists them.

**Headline:** a K'iche' word costs **2.68 tokens**, a Spanish word

More tokens per word means the model sees K'iche' as fragments rather than words:
it has to learn more from less, generation is slower, and a cloud API bills more for

### Method

- Tokenizer: `tokenizer.json` of `google/gemma-4-E2B-it` (from `GEMMA_BASE_MODEL`) loaded with
  Hugging Face `tokenizers`, special tokens off.
- Cross-check against Ollama `gemma4:e2b-it-qat` `prompt_eval_count`: 40/40 sentences match (our count + 1 BOS token).
- Words: whitespace-separated chunks containing at least one letter; apostrophes stay
  inside K'iche' words (`k'ak'` is one word). Text is normalized (`data/normalize.py`)
  first, so every glottal stop is the ASCII `'` — which the tokenizer splits off as its
  own token (`tz'i'` → `▁tz ' i '`), one reason K'iche' fertility is high.
- Data: non-religious sentence pairs from all splits; both columns measure the same content.
