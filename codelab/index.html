Por qué fallan los modelos sin contexto en el Longtail regional

Cuando un comercio en Guatemala reporta: «Tuvimos un gran clavo con el lote #804: el POS descontó dos veces el pisto del cliente por 450 baras y necesitamos resolverlo chispudo», un modelo invocado en Zero-Shot sin memoria local comete errores severos: interpreta pisto como bebida alcohólica, confunde baras con monedas genéricas y deja clavo o chispudo sin normalizar.

Tesis central de ingeniería (David vs. Goliath) En un dominio específico con vocabulario local (modismos nacionales de Guatemala, Colombia y México o lenguas de bajos recursos), un modelo compacto de pesos abiertos como Gemma 4 E2B (2.3B parámetros activos) supera la respuesta sin contexto cuando lo rodeamos de un sistema de datos curados, recuperación híbrida y verificación determinista.

Las 5 técnicas de ingeniería que implementarás en código

# Técnica de David vs. Goliath Función en server.mjs Qué problema resuelve
1 Glosario Curado + 0 Data Leaks + Glossary Dropout (85/15) verifyZeroDataLeaks() y applyGlossaryDropout() Impide que frases de evaluación se filtren al entrenamiento y oculta el 15% de las pistas durante el ajuste fino para que el modelo aprenda en sus pesos y no copie a ciegas.
2 Motor RAG Híbrido (BM25 + Dense + RRF k=60) con best_last retrieveHybridRRF() Combina coincidencia léxica exacta y similitud de subpalabras mediante Reciprocal Rank Fusion, ubicando el modismo más relevante al final del prompt para evitar Lost-in-the-Middle.
3 Duelo en Vivo + Consenso MBR-3 mbrSelectConsensus() y runSupportDuel() Compara la salida Zero-Shot frente al Especialista que genera 3 candidatos y elige el de mayor consenso promedio chrF++ contra las demás muestras.
4 Validador Determinista Post-Generación validateNormalizedTicket() Audita que ningún modismo regional quede crudo en el texto final y que el 100% de los números, horas y montos del ticket original se conserven intactos.
5 Evaluador chrF++ en código (0 a 100) computeChrFPlusPlus() Calcula al instante la similitud de n-gramas de caracteres (1..6) y palabras (1..2) frente a la referencia humana sin depender de un juez LLM.

2. Preparar el entorno con Ollama y Gemma 4 E2B

Duración estimada: 8 minutos

Toda la inferencia de SoporteLocal se ejecuta con Gemma 4 E2B (gemma4:e2b) corriendo localmente sobre Ollama, e incluye un modo determinista instantáneo de respaldo para que las pruebas unitarias corran en milisegundos incluso sin GPU dedicada.

Por qué Gemma 4 E2B corre con tan baja latencia

  • Per-Layer Embeddings (PLE): Aunque el checkpoint almacena tablas de embeddings por capa para un vocabulario amplio de 256,000 tokens, solo activa ~2.3B parámetros matemáticos por cada token generado.
  • Sliding Window Attention (5 a 1): Intercala 5 capas de atención local por cada capa de atención global, reduciendo el consumo de memoria KV Cache al inyectar glosarios regionales en el prompt.
  • Cuantización nativa QAT: Preserva la fidelidad en seguimiento de instrucciones y esquemas JSON ocupando menos de 2 GB de memoria.

3. Glosario Regional Curado, 0 Data Leaks y Glossary Dropout (85/15)

Duración estimada: 10 minutos

El primer pilar de nuestra arquitectura consiste en curar el banco de modismos de Guatemala (GT), Colombia (CO) y México (MX) junto con dos funciones de higiene de datos: verifyZeroDataLeaks() y applyGlossaryDropout().

Por qué es indispensable Glossary Dropout (85/15) en RAFT Cuando entrenamos o ajustamos un modelo con ejemplos aumentados por recuperación (Retrieval-Augmented Fine-Tuning), si el 100% de los prompts de entrenamiento contiene siempre el término exacto en el bloque de glosario, el modelo aprende un atajo perezoso: copia mecánicamente del contexto y falla cuando aparece una variante no recuperada. Con Glossary Dropout (85/15) mantenemos la pista en el 85% de los casos y la ocultamos determinísticamente en el 15% restante.

export function normalizeMatchKey(text) {
  return String(text || "")
    .normalize("NFD")
    .replace(/[\u0300-\u036f]/g, "")
    .toLowerCase()
    .replace(/[^\w\s]/g, " ")
    .replace(/\s+/g, " ")
    .trim();
}

export function verifyZeroDataLeaks(trainExamples, testExamples) {
  const trainKeys = new Set();
  for (const row of trainExamples || []) {
    if (row.source) trainKeys.add(normalizeMatchKey(row.source));
    if (row.target) trainKeys.add(normalizeMatchKey(row.target));
  }

  const leaks = [];
  for (const testRow of testExamples || []) {
    const sKey = normalizeMatchKey(testRow.source || "");
    const tKey = normalizeMatchKey(testRow.target || "");
    if (sKey && trainKeys.has(sKey)) leaks.push(`Fuga en source: "${testRow.source}"`);
    if (tKey && trainKeys.has(tKey)) leaks.push(`Fuga en target: "${testRow.target}"`);
  }

  return {
    passed: leaks.length === 0,
    leaks,
    trainCount: (trainExamples || []).length,
    testCount: (testExamples || []).length,
  };
}

export function applyGlossaryDropout(entries, rate = 0.15, seedKey = "soporte-local") {
  const keptEntries = [];
  const droppedEntries = [];

  for (let i = 0; i < entries.length; i++) {
    const entry = entries[i];
    const hashHex = crypto
      .createHash("sha1")
      .update(`${seedKey}:${entry.id || entry.idiom}:${i}`)
      .digest("hex");
    const bucket = (parseInt(hashHex.slice(0, 8), 16) % 10000) / 10000;
    if (bucket < rate) {
      droppedEntries.push(entry);
    } else {
      keptEntries.push(entry);
    }
  }

  const total = entries.length || 1;
  return {
    keptEntries,
    droppedEntries,
    dropoutRateTarget: rate,
    effectiveKeepRatio: Math.round((keptEntries.length / total) * 1000) / 1000,
  };
}

4. Motor RAG Híbrido (BM25 + Similitud Densa + RRF k=60) con orden best_last

Duración estimada: 10 minutos

Un buscador exclusivamente léxico falla cuando el usuario conjuga o pluraliza el modismo (por ejemplo, escribe camellando en lugar de camellar, o embolatadas en lugar de embolatado). Un buscador exclusivamente denso puede diluir modismos cortos de una sola palabra. Por eso implementamos Recuperación Híbrida con Reciprocal Rank Fusion (k=60).

Por qué el ordenamiento best_last mitiga Lost-in-the-Middle

En arquitecturas compactas con Sliding Window Attention como Gemma 4 E2B, los tokens situados al final del bloque de instrucciones —justo antes de la frase a transformar— reciben mayor peso atencional que los situados en la mitad superior del prompt. Invertir la lista recuperada para que el candidato #1 de RRF quede en la última línea del bloque de contexto (order: "best_last") mejora la adherencia terminológica sin agregar ni un milisegundo de latencia.

Implementar retrieveHybridRRF() en server.mjs

demo-app/server.mjs (Parte 2 — RAG Híbrido BM25 + Dense + RRF best_last)
export function retrieveHybridRRF(
  ticketText,
  { region = "ALL", k = 60, topN = 5, order = "best_last" } = {}
) {
  const normTicket = normalizeMatchKey(ticketText);
  const ticketTokens = new Set(normTicket.split(" ").filter(Boolean));
  const ticketNgrams = extractCharNgrams(ticketText);

  const pool = REGIONAL_GLOSSARY.filter(
    item => region === "ALL" || !region || item.region === region
  );

  // 1. Ranking Léxico BM25 sobre variantes exactas y tokens
  const bm25Scored = pool
    .map(entry => {
      let score = 0;
      for (const variant of entry.variants) {
        const normVar = normalizeMatchKey(variant);
        const varRegex = new RegExp(`\\b${normVar.replace(/\s+/g, "\\s+")}\\b`, "i");
        if (varRegex.test(normTicket)) score += 3.5;
      }
      return { entry, bm25Score: Math.round(score * 1000) / 1000 };
    })
    .sort((a, b) => b.bm25Score - a.bm25Score);

  // 2. Ranking Denso de subpalabras (captura conjugaciones como camellando / embolatadas)
  const denseScored = pool
    .map(entry => {
      const entrySurface = `${entry.idiom} ${entry.variants.join(" ")} ${entry.exampleSource}`;
      let sim = cosineMapSimilarity(ticketNgrams, extractCharNgrams(entrySurface));
      for (const variant of entry.variants) {
        const stem = normalizeMatchKey(variant).slice(0, 5);
        if (stem.length >= 4 && normTicket.includes(stem)) sim += 0.35;
      }
      return { entry, denseScore: Math.round(sim * 10000) / 10000 };
    })
    .sort((a, b) => b.denseScore - a.denseScore);

  // 3. Reciprocal Rank Fusion: score(d) = 1/(k + rank_bm25) + 1/(k + rank_dense), k = 60
  const rrfScores = new Map();
  bm25Scored.forEach((item, idx) => {
    if (item.bm25Score > 0) {
      rrfScores.set(item.entry.id, (rrfScores.get(item.entry.id) || 0) + 1 / (k + idx + 1));
    }
  });
  denseScored.forEach((item, idx) => {
    if (item.denseScore > 0.08) {
      rrfScores.set(item.entry.id, (rrfScores.get(item.entry.id) || 0) + 1 / (k + idx + 1));
    }
  });

  let merged = pool
    .filter(entry => rrfScores.has(entry.id))
    .map(entry => ({
      id: entry.id,
      region: entry.region,
      idiom: entry.idiom,
      standard: entry.standard,
      rrfScore: Math.round((rrfScores.get(entry.id) || 0) * 100000) / 100000,
    }))
    .sort((a, b) => b.rrfScore - a.rrfScore)
    .slice(0, topN);

  // Orden best_last: el modismo de mayor puntaje RRF se ubica al final del bloque RAG
  if (order === "best_last") {
    merged = [...merged].reverse();
  }

  return { order, rrfK: k, hits: merged, topHitAtEnd: merged[merged.length - 1] || null };
}

5. Evaluador chrF++, Consenso MBR-3 y Validador Determinista

Duración estimada: 10 minutos

En este paso implementamos tres componentes deterministas que convierten a un modelo pequeño en un sistema confiable de grado productivo:

  1. computeChrFPlusPlus(hypothesis, reference): Calcula el F-score armónico (con beta = 2) combinando n-gramas de caracteres de orden 1 a 6 y n-gramas de palabras de orden 1 a 2 en escala de 0 a 100.
  2. mbrSelectConsensus(candidates) (Minimum Bayes Risk con 3 muestras): Toma 3 candidatos generados para el mismo ticket, calcula el chrF++ de cada candidato contra los otros dos y elige el de mayor soporte promedio, filtrando alucinaciones aisladas.
  3. validateNormalizedTicket(output, sourceText, detectedIdioms): Verifica que ningún modismo regional detectado haya quedado sin normalizar en la salida y que el 100% de las cifras del ticket original (como 14:30, 804 y 450) estén presentes en el texto normalizado.
demo-app/server.mjs (Parte 3 — chrF++, MBR-3 y Validador Post-Generación)
export function computeChrFPlusPlus(hypothesis, reference) {
  const hypClean = String(hypothesis || "").trim().replace(/\s+/g, " ");
  const refClean = String(reference || "").trim().replace(/\s+/g, " ");
  if (!hypClean || !refClean) return 0;
  if (hypClean === refClean) return 100;

  const hypChars = Array.from(hypClean.replace(/\s+/g, ""));
  const refChars = Array.from(refClean.replace(/\s+/g, ""));
  const hypWords = hypClean.toLowerCase().replace(/[.,;:!?()"]/g, "").split(" ").filter(Boolean);
  const refWords = refClean.toLowerCase().replace(/[.,;:!?()"]/g, "").split(" ").filter(Boolean);

  const charF = ngramFScore(hypChars, refChars, 6, 2);
  const wordF = ngramFScore(hypWords, refWords, 2, 2);
  return Math.round(((charF * 6 + wordF * 2) / 8) * 1000) / 10;
}

export function mbrSelectConsensus(candidates) {
  const cleaned = (candidates || []).map(c => String(c || "").trim()).filter(Boolean);
  const candidatesWithSupport = cleaned.map((candI, i) => {
    let sum = 0;
    let count = 0;
    for (let j = 0; j < cleaned.length; j++) {
      if (i === j) continue;
      sum += computeChrFPlusPlus(candI, cleaned[j]);
      count++;
    }
    return {
      index: i,
      text: candI,
      supportScore: Math.round((sum / (count || 1)) * 10) / 10,
    };
  });

  const best = candidatesWithSupport.reduce((a, b) => (b.supportScore > a.supportScore ? b : a));
  return { selected: best.text, selectedIndex: best.index, candidatesWithSupport };
}

export function validateNormalizedTicket(outputText, sourceText, detectedIdioms = []) {
  const normOut = normalizeMatchKey(outputText);
  const untranslatedIdioms = [];

  for (const hit of detectedIdioms) {
    const entry = REGIONAL_GLOSSARY.find(g => g.id === hit.id || g.idiom === hit.idiom) || hit;
    const variants = entry.variants || [entry.idiom];
    const stillHasRaw = variants.some(v =>
      new RegExp(`\\b${normalizeMatchKey(v).replace(/\s+/g, "\\s+")}\\b`, "i").test(normOut)
    );
    if (stillHasRaw) untranslatedIdioms.push(entry.idiom);
  }

  const rawNumbers = String(sourceText || "").match(/\d+(?:[.,:]\d+)?/g) || [];
  const outNumbers = new Set(String(outputText || "").match(/\d+(?:[.,:]\d+)?/g) || []);
  const preservedNumbers = rawNumbers.filter(n => outNumbers.has(n));
  const missingNumbers = rawNumbers.filter(n => !outNumbers.has(n));

  return {
    passed: untranslatedIdioms.length === 0 && missingNumbers.length === 0,
    untranslatedIdioms,
    preservedNumbers,
    missingNumbers,
  };
}

test("1. verifyZeroDataLeaks y applyGlossaryDropout (85/15) protegen las particiones", () => {
  const trainSet = [
    { source: "El sistema me descontó el pisto dos veces.", target: "El sistema me descontó el saldo disponible dos veces." },
  ];

    { source: PRESET_TICKETS[0].ticketText, target: PRESET_TICKETS[0].humanReference },

  assert.equal(dropout.keptEntries.length + dropout.droppedEntries.length, REGIONAL_GLOSSARY.length);
  assert.ok(dropout.effectiveKeepRatio >= 0.7 && dropout.effectiveKeepRatio <= 0.95);

test("2. retrieveHybridRRF combina BM25 + Dense con RRF (k=60) y ordena con best_last", () => {

  const lastScore = rag.hits[rag.hits.length - 1].rrfScore;

test("3. mbrSelectConsensus (MBR-3) elige el candidato con mayor consenso chrF++", () => {

  assert.equal(check.passed, true);
  assert.deepEqual(check.preservedNumbers, ["14:30", "804", "450"]);

test("5. runSupportDuel demuestra ventaja del Especialista sobre Zero-Shot en GT, CO y MX", async () => {
